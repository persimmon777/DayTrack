# DayTrack: архитектура и план работ

Приложение для iPhone (iOS 17.4+), в котором ты составляешь план дня, вносишь, что было на самом деле, и видишь разницу. Поверх этого работают подсказки по балансу учёбы и отдыха, графики, фокусы недели и месяца и текстовый отчёт для нейросети.

Документ фиксирует все решения, принятые до начала разработки. Если что-то меняется по ходу, сначала правится этот документ.

## 2. Ограничения, о которых нужно знать заранее

- **Бесплатный Apple ID.** Приложение нужно переподписывать через iloader каждые 7 дней. Данные при этом сохраняются, пока приложение не удалено с телефона. iCloud-синхронизации нет.
- **Разработка идёт без Mac.** Код пишется в Linux, собирается на серверах GitHub. Запустить приложение и посмотреть на экран можешь только ты, поэтому после каждого этапа нужна твоя проверка на телефоне.
- **Виджет и таймер отдыха при установке через iloader не проверены.** Виджету нужен общий с приложением контейнер данных (App Group), и не все способы установки настраивают его правильно. Это проверяется в самой первой сборке (этап 0).
- **Виджет обновляется не мгновенно.** iOS сама решает, когда его перерисовать. Он обновится после каждого изменения в приложении и несколько раз в день по расписанию.
- **Таймера учёбы нет**, так как факт вносится вручную. Поэтому подсказки о перерывах строятся по плану (длинный блок учёбы без паузы) и по таймеру отдыха, а не по тому, сколько ты реально сидишь.
- **Таймер на экране блокировки живёт до 8 часов.** Это ограничение iOS для Live Activity.

## 4. Устройство проекта

```
project.yml                  описание проекта для XcodeGen
App/                         приложение: экраны и навигация
  Features/Today/            план, факт, сравнение
  Features/Focus/            фокусы недели и месяца
  Features/Analytics/        графики и отчёт
  Features/Rest/             таймер отдыха
  Features/Review/           вечерняя рефлексия
  Features/Settings/         категории, расписание, шаблоны, темы, копии
  Data/                      модели SwiftData, сохранение, резервные копии
  Services/                  уведомления, синхронизация виджета, Live Activity
Widgets/                     расширение: виджет баланса и таймер отдыха
Shared/                      общее для приложения и виджета: снимок данных, темы
Packages/DayTrackCore/       чистая логика без интерфейса, с тестами
.github/workflows/build.yml  сборка .ipa
docs/                        этот документ и инструкция по установке
```

Три слоя, зависимости идут только сверху вниз:

1. **Экраны** (`App/Features`) показывают данные и принимают действия.
2. **Данные и сервисы** (`App/Data`, `App/Services`) хранят записи, ставят уведомления, обновляют виджет.
3. **Ядро** (`DayTrackCore`) считает всё: сравнение плана с фактом, метрики, подсказки, текст отчёта. Оно не знает ни про экраны, ни про базу, принимает простые структуры и возвращает простые структуры.

Ядро вынесено отдельно, потому что его можно проверять автоматическими тестами при каждой сборке. Это главная страховка при разработке без Mac: вся арифметика и правила подсказок проверяются до того, как сборка попадёт к тебе.

## 5. Модель данных

| Сущность | Что хранит |
|---|---|
| `Category` | Название, цвет, иконка, тип (учёба, отдых, сон, спорт, быт, дорога, работа, другое). Тип нужен для расчёта баланса |
| `Focus` | Название, «зачем», период (неделя или месяц), дата начала периода, родительский фокус месяца, статус, итог |
| `Day` | Дата, состояние (черновик, зафиксирован, закрыт), время фиксации |
| `PlannedBlock` | Блок плана: название, категория, начало, конец, фокус, размер (большое, среднее, мелкое), признак «лягушка», откуда взят (вручную, расписание, шаблон) |
| `PlanChange` | Правка плана после фиксации: что изменено, значения до и после, когда |
| `TaskItem` | Задача без времени: название, категория, оценка в минутах, размер, фокус, статус |
| `FactEntry` | Запись факта: начало, конец, название, категория, ссылка на блок плана или задачу, фокус, признак «вне плана», причина отклонения |
| `EnergyMark` | Отметка энергии и настроения (1–5) со временем |
| `Reflection` | Вечерняя рефлексия: что получилось, что помешало, что изменить завтра, оценка дня |
| `ScheduleRule` | Правило расписания: день недели, время, название, категория, период действия, чётность недели |
| `DayTemplate` | Именованный шаблон дня со списком блоков |
| `RestSession` | Сеанс отдыха: начало, запланированная длительность, фактический конец |

Настройки (время подъёма и отбоя, целевой баланс, потолок учёбы, время уведомлений, тема, текст запроса для нейросети) хранятся отдельно от базы.

Решения по модели:

- **Граница дня настраивается**, по умолчанию 04:00. Всё, что сделано в два часа ночи, относится к предыдущему дню. Блок сна может переходить через полночь и засчитывается дню, в который ты проснулся.
- **Чётность недели в расписании.** Пары в вузах часто идут по чётным и нечётным неделям, поэтому правило расписания может действовать каждую неделю или через одну.
- **Серии не хранятся**, а вычисляются из дней.
- **Версия схемы данных** ведётся с первой сборки, чтобы обновления приложения не ломали накопленные записи.

## 6. Ключевая логика

### Жизнь одного дня

1. **Черновик.** План свободно редактируется. Расписание на этот день недели подставляется автоматически, можно применить шаблон.
2. **Фиксация.** Происходит по кнопке «План готов» либо автоматически в момент начала первого блока. Сохраняется исходная версия плана.
3. **День идёт.** Правки плана разрешены, каждая записывается как `PlanChange`. Факт вносится в любой момент: нажимаешь на блок плана, открывается форма с уже подставленным временем, ты поправляешь начало и конец. Дела вне плана добавляются отдельно, с причиной.
4. **Вечерний разбор.** Для блоков без факта приложение спрашивает причину. Затем короткая рефлексия.
5. **Закрыт.** День попадает в аналитику и отчёты.

### Сравнение плана и факта

Каждый блок плана получает статус:

- **выполнен**: факт покрывает не меньше 90% запланированного времени;
- **частично**: факт есть, но меньше;
- **не выполнен**: факта нет, спрашивается причина;
- **сдвинут**: начало отличается от плана больше чем на 15 минут.

Метрики:

| Метрика | Как считается |
|---|---|
| Выполнение плана | Сумма по блокам min(факт, план) в минутах, делённая на запланированные минуты. Считается дважды: к исходному плану и к плану с правками |
| Выполнение задач | Доля задач без времени со статусом «сделано» |
| Точность оценок | Отношение фактической длительности к плановой по категориям, медиана за последние недели |
| Сдвиг старта | Среднее опоздание с началом блоков |
| Баланс | Фактические минуты по типам категорий против целевых долей |
| Причины отклонений | Сколько раз каждая причина сорвала блок или породила дело вне плана |
| Энергия по часам | Средняя отметка энергии для каждого часа суток |
| Прогресс фокуса | Фактические часы и выполненные дела, привязанные к фокусу |

### Советчик

Набор независимых правил. Каждое смотрит на план дня и историю и возвращает подсказку: текст, объяснение «почему» и действие в одно нажатие, если оно возможно. Работает на телефоне, без сети и без нейросети. Любое правило отключается в настройках.

| Правило | Когда срабатывает | Что предлагает |
|---|---|---|
| Лягушка | В плане нет главного дела или оно стоит поздно | Отметить лягушку и поставить её первым блоком учёбы |
| Старт на 5 минут | Лягушка не начата к середине дня | Начать с пятиминутного шага, а не со всего дела |
| Поправка оценок | По категории накоплена статистика, факт стабильно длиннее плана | Увеличить блок на свой обычный процент |
| Лимит загрузки | Занято больше 70% времени бодрствования | Убрать или перенести дела |
| Правило 1-3-5 | Больше одного большого, трёх средних, пяти мелких дел | Перенести лишнее на другой день |
| Резерв | В дне нет блока «на непредвиденное» | Добавить резерв, по умолчанию 60 минут |
| Перерыв | Учёба идёт подряд дольше выбранного интервала | Вставить перерыв |
| Отдых в плане | В дне нет ни одного блока отдыха | Добавить отдых как полноценный блок |
| Потолок учёбы | Учёбы больше заданного дневного потолка | Сократить, чтобы не работать до упора |
| Сон | Блок сна короче 7 часов | Сдвинуть отбой или подъём |
| День-минимум | Два и больше дней без плана | Составить минимальный день: один блок по фокусу от 25 минут и вечерний разбор |
| Продуктивные часы | Накоплено две недели отметок энергии | Ставить сложное на часы с высокой энергией |
| Дисбаланс недели | Учёба или отдых за неделю сильно отклонились от цели | Скорректировать оставшиеся дни |

Пороги (70%, 60 минут, потолок учёбы, длина интервалов) меняются в настройках.

### На чём основаны подсказки

| Приём | Источник | Насколько надёжно |
|---|---|---|
| Поправка оценок по своей статистике | Ошибка планирования: Kahneman & Tversky, 1979; Buehler, Griffin & Ross, 1994 | Хорошо подтверждено: люди систематически недооценивают сроки, и взгляд на прошлые похожие дела это исправляет |
| Короткие перерывы | Метаанализ микроперерывов: Albulescu и др., 2022; Ariga & Lleras, 2011 | Перерывы надёжно снижают усталость; влияние на результат слабее и зависит от задачи |
| Перерывы по расписанию, а не «когда устану» | Biwer и др., 2023 | Одно исследование на студентах: при заданных заранее перерывах меньше усталость и отвлечения |
| Отдых без мыслей об учёбе | Исследования восстановления: Sonnentag & Fritz, 2007 | Хорошо подтверждено: восстанавливает отдых с переключением, а не отдых с тревогой о делах |
| Дружелюбный тон без вины | Wohl, Pychyl & Bennett, 2010 | Студенты, простившие себе прокрастинацию, меньше прокрастинировали перед следующим экзаменом |
| Отслеживание прогресса | Метаанализ Harkin и др., 2016 | Хорошо подтверждено: регулярная сверка с целью повышает шанс её достичь |
| План «если — то» для старта | Намерения реализации: Gollwitzer, 1999 | Хорошо подтверждено для запуска действий |
| Сон от 7 часов | Рекомендации AASM и Sleep Research Society, 2015 | Консенсус специалистов для взрослых |
| Интервалы 25/5, 50/10, 90/20 | Практика (метод Помодоро и подобные) | Конкретные числа наукой не закреплены, это удобные значения по умолчанию; выбираются под дело |
| «Лягушка», правило 1-3-5, резерв | Практика тайм-менеджмента | Не исследования, а рабочие приёмы; включены, потому что отвечают на твои ответы в тесте |

Приложение не выдаёт практические приёмы за научные факты: в объяснении «почему» у каждой подсказки указано, исследование это или практика.

### Мягкие серии

Считается день, в котором есть план и вечерний разбор. Один пропуск в неделю серию не рвёт. Рядом всегда показывается «дней с планом за последние 30», чтобы обрыв серии не обнулял ощущение прогресса. Процент выполнения на серию не влияет: засчитывается сам факт планирования и разбора.

## 7. Экраны

Четыре вкладки:

1. **Сегодня.** Сверху фокусы недели, лягушка и индикатор загрузки. Ниже две шкалы времени рядом: план слева, факт справа. Под ними задачи без времени. Кнопки: добавить блок, внести факт, начать отдых, отметить энергию. Переключение дат листанием.
2. **Фокусы.** Фокусы текущей недели и месяца с прогрессом, история прошлых периодов.
3. **Аналитика.** Переключатель день, неделя, месяц. Графики, календарь и кнопка «Отчёт для нейросети».
4. **Настройки.** Категории, расписание, шаблоны, целевой баланс и пороги советчика, уведомления, тема, резервные копии, текст запроса для нейросети.

Отдельные сценарии: первый запуск (подъём и отбой, целевой баланс, расписание, разрешение на уведомления), вечерний разбор, таймер отдыха.

### Календарь

В аналитике есть календарь, в котором можно выбрать любой день и посмотреть, какими были план и факт.

- Месяцы листаются назад и вперёд, есть быстрый переход к нужному месяцу и году и кнопка «Сегодня».
- Каждый день окрашен по проценту выполнения плана, так что календарь одновременно служит тепловой картой. Дни без плана остаются пустыми, дни с планом, но без внесённого факта помечены отдельно.
- Нажатие на день открывает его страницу: две шкалы времени (план и факт), статусы блоков, дела вне плана с причинами, правки плана, итоговые цифры, отметки энергии и рефлексия.
- Со страницы прошлого дня можно довнести или исправить факт и скопировать отчёт за этот день. План прошлого дня не редактируется.

| Прогресс по фокусам | Горизонтальные полосы | Неделя, месяц |

## 8. Отчёт для нейросети

Кнопка собирает текст и копирует его в буфер вместе с запросом. Перед копированием текст виден целиком. Запрос по умолчанию просит разобрать отчёт с позиции психолога и редактируется в настройках.

Примерный вид отчёта за день:

```
ОТЧЁТ ЗА ДЕНЬ: вторник, 10 ноября

Фокусы недели: курсовая (шаг к фокусу месяца «сдать сессию без долгов»)
Лягушка дня: глава 2 курсовой — частично

ПЛАН → ФАКТ
09:00–10:30 Пары, матанализ → 09:00–10:30, выполнено
11:00–13:00 Курсовая, глава 2 → 12:10–13:00, частично (50 из 120 мин), причина: трудно начать
13:00–13:30 Обед → 13:00–14:10
15:00–16:30 Английский → не выполнено, причина: внезапное дело

ВНЕ ПЛАНА
14:10–16:00 Помощь соседу с переездом, причина: внезапное дело

ИТОГИ
Выполнение плана: 58% (к исходному плану), 64% (с правками)
Учёба: план 5 ч, факт 2 ч 20 мин
Отдых: план 2 ч, факт 3 ч 40 мин
Сон: 6 ч 30 мин
Энергия: 10:00 — 4, 14:00 — 2, 19:00 — 3

РЕФЛЕКСИЯ
Получилось: ...
Помешало: ...
Завтра изменю: ...
```

Отчёты за неделю и месяц содержат динамику по дням, баланс, точность оценок, частые причины отклонений, прогресс по фокусам и сравнение с прошлым периодом.

## 9. Виджет, таймер отдыха, уведомления

**Виджет баланса.** Малый и средний размер. Показывает фактическое соотношение учёбы, отдыха и сна против цели, за сегодня или за неделю (выбирается в настройке виджета). Приложение при каждом изменении записывает небольшой файл-снимок в общий контейнер, виджет читает только его. К базе данных виджет не обращается.

**Таймер отдыха.** Запускается из приложения: 5, 10, 15, 20, 30 минут или своё значение. На экране блокировки идёт обратный отсчёт и написано, к чему возвращаться. Когда время вышло, приходит уведомление, и ещё одно через 10 минут, если ты не вернулся. Кнопка «Я вернулся» записывает отдых в факт с реальной длительностью. Если отдых затянулся, приложение без упрёков предлагает записать его как есть: честные данные важнее красивых.

**Уведомления.**

| Уведомление | Когда |
|---|---|
| Утро | В заданное время: составить или проверить план |
| Вечер | В заданное время: внести факт и подвести итоги |
| Внести факт | Один-два раза в день в заданное время; отменяется, если факт уже внесён |
| Перерыв | В середине длинного запланированного блока учёбы без паузы |
| Конец отдыха | По таймеру отдыха |

Каждый вид отключается отдельно.

## 10. Резервные копии

- Данные хранятся в базе внутри приложения.
- Ты один раз выбираешь папку в «Файлах». Лучше iCloud Drive: папка самого приложения удаляется вместе с ним, а iCloud Drive нет.
- Раз в день приложение кладёт туда копию в формате JSON и хранит несколько последних.
- В настройках есть «Сохранить копию сейчас» и «Восстановить из копии».
- Копии делаются с этапа 1, как только появляются настоящие данные.

Чтобы данные не терялись при обновлении, приложение всегда нужно ставить поверх старого через тот же Apple ID, не удаляя его.

## 11. Темы оформления

Тема задаёт набор цветов: акцент, фон, поверхности, цвета категорий на графиках. Планируются четыре:

| Тема | Характер |
|---|---|
| Системная | Как приложения Apple, светлая и тёмная следуют за системой |
| Спокойная | Приглушённые цвета, много воздуха |
| Яркая | Насыщенные цвета категорий, крупные цифры |
| Ночная | Всегда тёмная |

## 12. Сборка и проверка

1. Изменения попадают в репозиторий.
2. GitHub Actions запускает тесты ядра, создаёт проект через XcodeGen и собирает приложение без подписи.
3. Готовый `.ipa` появляется на странице Releases репозитория.
4. Ты скачиваешь его на компьютер и ставишь через iloader, который подписывает приложение твоим Apple ID.

Что проверяется автоматически: приложение компилируется, логика ядра проходит тесты. Что можешь проверить только ты: как всё выглядит и ведёт себя на телефоне. После каждого этапа будет короткий список, что открыть и на что посмотреть.

## 13. Этапы

### Этап 0. Каркас и проверка установки

Цель: убедиться, что цепочка «код → сборка → iloader → телефон» работает и что рискованные части iOS заводятся.

- Проект, сборка в GitHub Actions, публикация `.ipa`.
- Пустое приложение с четырьмя вкладками.
- Тестовый виджет, показывающий число, которое записало приложение.
- Тестовый таймер на экране блокировки и тестовое уведомление.
- Инструкция по установке простыми словами.

Ты проверяешь: приложение открывается, виджет добавляется и показывает число из приложения, таймер виден на экране блокировки, уведомление приходит.

### Этап 1. План, факт, сравнение

- Категории с редактированием.
- План дня: блоки на шкале времени и задачи без времени.
- Фиксация плана и журнал правок.
- Ввод факта, дела вне плана с причинами.
- Сравнение плана и факта на двух шкалах, статусы блоков, процент выполнения.
- Расписание по дням недели с чётностью, шаблоны дня.
- Резервные копии.

Ты проверяешь: можешь прожить с приложением обычный день от плана до сравнения.

### Этап 2. Фокусы, аналитика, отчёт

- Фокусы недели и месяца, привязка блоков и задач.
- Отметки энергии и настроения.
- Вечерний разбор с рефлексией.
- Все графики за день, неделю, месяц.
- Календарь с переходом к плану и факту любого дня.
- Текстовый отчёт с запросом для нейросети.

Ты проверяешь: графики понятны, в календаре открывается любой прошлый день, отчёт после вставки в нейросеть даёт осмысленный разбор.

### Этап 3. Виджет, таймер отдыха, уведомления

- Виджет баланса.
- Таймер отдыха с записью в факт.
- Все уведомления с настройками.

Ты проверяешь: виджет показывает верные данные, отдых на 15 минут действительно заканчивается напоминанием.

### Этап 4. Советчик и оформление

- Правила советчика с объяснениями «почему».
- Мягкие серии и день-минимум.
- Экран первого запуска.
- Темы оформления.

Советчик идёт последним намеренно: поправке оценок и поиску продуктивных часов нужны данные, которые ты накопишь за этапы 1–3.

## 14. Риски и открытые вопросы

| Риск | Что делаем |
|---|---|
| Виджет не получает данные при установке через iloader | Проверяем на этапе 0. Если не работает, ищем способ передачи данных или обсуждаем отказ от виджета |
| Ошибки интерфейса, которые не видны без запуска | Короткие этапы и твоя проверка после каждого; попробую настроить в сборке автоматические снимки экрана из симулятора |
| Потеря данных при переустановке | Автокопия во внешнюю папку с этапа 1 |
| Ручной ввод факта надоедает | Форма с подставленным из плана временем. Если всё равно тяжело, позже можно добавить кнопку «как в плане» |
| Срок подписи 7 дней | Напоминание о переподписи в инструкции |
